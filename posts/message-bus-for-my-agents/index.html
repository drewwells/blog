HOMELAB / AGENT INFRASTRUCTURE

I built a message bus so my AI agents could run my servers.

A custom WebSocket bus, leader election, and a Telegram voice bridge turn a five-machine homelab — Linux and macOS alike — into a fault-tolerant organization of AI agents that supervises itself, keeps the apps up, and pages me when it's stuck.

01
The substrate

Five machines, one logical fabric

Most homelabs are a pile of containers on one box. This one is a small fleet — every node joined into a single Tailscale mesh so an agent on one machine can address an agent on another as if they were local.

There's a catch the design has to absorb: the house runs on T-Mobile home internet with no public IPv4 and blocked IPv6 ingress. So a pair of cheap cloud VPS exist for one reason — to be a stable IPv4 egress point in front of the LAN. Everything real still runs at home, on hardware I own.

02
The bridge — centerpiece

A cross-machine message bus for agents

Claude Code agents are isolated processes with limited context. To behave like an organization — a COO delegating to PMs and coders across machines — they need to find each other, message each other reliably, and never collide on identity. The bridge is a two-layer Go system that gives them exactly that.

A single hub at ws://amazon.home.arpa:8991 is the WebSocket router and registry of live sessions. Alongside each agent runs a bridge MCP server that exposes the hub as tools the model calls directly — register, send, get_messages, ack, status, list_peers, hub_status, leader_status. Every agent is addressed as name@machine; queues are machine-scoped; the namespace is human-readable over a distributed fabric.

  • Identity-collision detection. Supervisors relaunch agents at will, so the hub refuses a duplicate identity while a live process holds it. "Live" means a heartbeat within 60s — after that the old registration is a corpse and a fresh claim takes over. The line between "restarted cleanly" and "split-brain."
  • Lease-based leader election. A claim_role succeeds only if no live lease exists. Lease generations tell a renewal (same gen) apart from a true handover (primary_changed). Same shape as etcd / ZooKeeper, hand-rolled for an agent fleet.
  • Explicit acks. A message store with ack / status semantics, so a sender can confirm a peer actually received a message — not just that it was sent.

"The COO role is a lease, not a title. If the agent holding it stops sending heartbeats for sixty seconds, the lease expires and someone else can take over — but only on the one machine the code allows to hold it."

— On leader election
03
The Telegram relay

A phone as the control plane

I'm not always at a terminal. The relay turns a Telegram chat into a first-class, secured interface to the fleet — bidirectional, so agents escalate to me and I command them back. The headline feature: I can leave my servers a voice memo.

Telegram voice notes (OGG/Opus) get piped through a local Whisper client — transcription runs on my own hardware, not a cloud STT vendor — and land as text in the right agent's queue. Real access control sits in front: an open / pairing / closed DM policy, an allowlist, a pairing handshake, and group→agent routing so different chats talk to different agents.

Long agent replies get split to respect Telegram's 4096-char cap, and a typed-message convention keeps ops chatter separate from real input on the wire: [OPS-PROBE] for liveness, [OPS] for instructions, [USER-RELAY] for a forwarded human message.

"I can leave my servers a voice memo. Whisper turns it into text, the bridge routes it to the right agent, and the agent acks back — or the relay tells me it went unheard."

— On the relay
04
Keeping it alive

Supervision, local models, memory

The unglamorous third act — the parts that make it stay up unattended, across two operating systems whose service models barely resemble each other.

Cross-platform supervision. Linux uses systemd; the Mac uses launchd. Per-agent supervisors restart crashed agents and wedged hubs under one shared model — with a hard-won rule baked in: a supervisor must never evict a session I'm actively attached to. It only kills and recreates a pane when the process is genuinely dead.

  • On-prem LLM serving. OpenAI-compatible local inference via Apple MLX on beast, daemon-managed. Fallback chain local Qwen → local Gemma → cloud Claude, so no single machine is a hard dependency.
  • Persistent memory. A 245-entry knowledge base synced across machines with Syncthing. Agents survive periodic context wipes by re-reading a state.md source-of-truth on every fresh boot.
  • "Dream" consolidation. A nightly 04:30 timer mines recent transcripts for durable insights, runs a headless claude -p pass to merge duplicates, guards the result with seven validation checks, atomically swaps it in, and Telegrams me a one-line PASS/FAIL.

Cross-cutting themes

Why this is the interesting part

01
Agents as operators, not chatbots
The claim isn’t "I use an LLM." It’s a fleet of agents, with an elected leader, that runs my infrastructure and pages me when stuck.
02
Distributed-systems fundamentals, hand-rolled
Leader election, leases, heartbeats, identity arbitration, at-least-once messaging with acks — applied to a problem most people solve with hope.
03
Sovereignty by default
Own hardware, own LLMs, own message bus, own speech-to-text. The cloud droplet exists only because the ISP won’t hand out an IPv4.
04
Operational maturity
Watchdogs that respect human-attached sessions, memory with backups and seven-check validation, PASS/FAIL phone alerts — the work that separates a toy from a thing you trust.
END OF DISPATCH
An addressable, fault-tolerant fabric — with a single elected leader, at-least-once messaging, and a phone for a console.
